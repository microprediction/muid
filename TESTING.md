# Test plan

Tests are written and committed before the code they govern, and are seen to fail first. A layer's code is merged only
when its whole section here passes, including the anti-vacuity checks. Rule labels refer to `SPEC.md`.

## 1. Rules for every test

- **One invariant per file:** `tests/<layer>/<label>-<name>.test.mjs`. Mutation testing tracks coverage per file, so
  small files keep it precise and fast.
- **Runner:** `node --test`, no other runner. Property tests use fast-check with a fixed seed in CI and a printed seed
  on failure.
- **Vectors are data, not code.** `tests/vectors/<set>/` holds the files exactly as published, plus `SOURCE.md`
  (URL, upstream commit, SHA-256 of each file, licence). A test checks those hashes before using the files.
- **Expected outputs come from outside the code under test:** written by hand, taken from a published vector set, or
  produced by an independent reference. Never generated by the implementation being tested.
- **Anti-vacuity, enforced by tests themselves:**
  - every vector suite asserts the exact number of cases it ran;
  - every property asserts, from fast-check statistics, that most generated inputs exercised the accept path (or the
    reject path, for a reject property);
  - every guard has a broken twin (§4) that the suite must fail against;
  - a skipped or `todo` test fails CI.
- **Rejects are specific.** A reject test asserts the reason code, so a case rejected for the wrong reason fails.

## 2. Layer 1 — encoding (`src/encode.js`): E1, E2, E3

Interface under test: `encode(value) -> string`, `decode(text) -> frozen value`. Both throw `EncodingError` with a
reason code on refusal.

### 2.1 Known answers

- **RFC 8785 reference vectors** (cyberphone `testdata/`, pinned; see `tests/vectors/jcs/SOURCE.md`). None of the six
  cases lies inside our value domain, so (a) each must be refused with its E5 reason, and (b) every string key and
  value in the upstream *outputs* is cut as raw bytes and wrapped as `{"s": …}`; our encoder must reproduce those
  upstream bytes exactly. This is the independent check of string escaping.
- **Hand-written vectors**, written as literals in the test files (`E1-hand-vectors`, `E2-decode-refusals`,
  `E3-value-refusals`): the expected bytes or reason for each case are typed by hand, never computed.
- The reference implementation used in P4 formats strings with `JSON.stringify`, as an encoder of ours would, so P4
  cannot catch a string-escaping error common to both; the upstream vectors above cover that.

### 2.2 Adversarial cases (every one has a vector)

| Input | Expected |
|---|---|
| key `__proto__`, `toString`, `hasOwnProperty` | refused (grammar: leading underscore, uppercase) |
| key `constructor`, `valueof` | encode and decode as ordinary own keys |
| one object reachable by 2^15 paths (a "diamond") | refused with `size` in well under a second (E4) |
| UTF-8 output of exactly 65,536 bytes; of 65,538 bytes with only 32,773 UTF-16 code units | accepted; refused (`size` counts bytes, not code units) |
| keys `"1"`, `"10"`, `"A"`, `""`, a 33-character key, a key with a lone surrogate | refused (grammar) |
| a 32-character key | accepted |
| keys inserted in different orders | identical bytes |
| array hole, `undefined` element, array with an extra own property | refused |
| `-0`, `NaN`, `±Infinity`, `1.5`, `2**53`, `-(2**53)` | refused |
| `2**53 - 1`, `-(2**53 - 1)`, `0` | accepted |
| `null` at any depth; `undefined` as a value | refused |
| BigInt, function, symbol value, symbol key, `Date`, `Map`, `Set`, `RegExp`, typed array, `ArrayBuffer`, class instance, boxed primitive | refused |
| object with an accessor property, a non-enumerable property, or a non-plain prototype | refused |
| cycle; shared subobject at two paths | cycle refused; sharing encodes as its expansion |
| nesting deeper than `MAX_DEPTH`; output longer than `MAX_BYTES` | refused before any stack overflow (E4) |
| **decode** text longer than `MAX_BYTES` | refused without calling `JSON.parse` (E4; checked with a spy) |
| string with lone high or low surrogate; with U+2028, U+2029, U+FEFF, U+0000–U+001F, `"`, `\` | lone surrogates refused; the rest match JCS escaping |
| top-level value that is not an object | refused |
| **decode** text with whitespace, a trailing newline, a BOM, a duplicate key, keys out of order, `\/`, `é` where the canonical form is literal, uppercase `\u001F`, `1e0`, `1.0`, `-0`, a leading zero | refused (E2) |
| **decode** text that `JSON.parse` accepts but that re-encodes differently | refused (E2) |

### 2.3 Properties (fast-check)

- **P1 round trip:** for generated in-domain values, `decode(encode(v))` deep-equals `v`. Implies E1.
- **P2 order independence:** permuting key insertion order at every level never changes `encode(v)`.
- **P3 canonical input:** for any valid encoding `b` and any single-byte mutation, insertion or deletion `b'`,
  `decode(b')` either throws or `encode(decode(b')) === b'`.
- **P4 reference agreement:** for in-domain `v`, `encode(v)` equals the output of an independent RFC 8785
  implementation (dev dependency, pinned).
- **P5 refusal is total:** values from an out-of-domain generator always throw `EncodingError`, never return, and
  never throw anything else.
- **P6 frozen output:** every object and array returned by `decode` is frozen, and so is everything inside it.

Generators cover deep and wide nesting, every string class in §2.2, and integers concentrated near ±2^53 and 0.

### 2.3a Hostile inputs (from adversarial review)

- **H1 resource bounds:** 1e8-character strings (including NUL, whose escaped form exceeds the engine's string limit),
  arrays and objects one element past their width bound, sparse length 2^32 − 1, a dense 2e6-element array: each
  refused for `size` on entry, quickly, and never with a foreign error.
- **H2 Proxies:** traps that throw Errors or non-Errors, revoked proxies, missing descriptors, invariant-breaking
  `ownKeys`, a nested proxy mutating its parent, lengths that change between reads or are not non-negative safe
  integers; and a counting proxy that proves every trap runs at most once per object and property (E6).
- **H3 internal slots:** each detected kind refused when given a plain or null prototype; the residual kinds pinned
  to their documented behaviour.
- **H4 patched built-ins:** 30 built-ins patched after loading (RegExp exec/test, isWellFormed, sort, Number checks,
  JSON, reflection, freeze, iteration, call/apply, the slot checks); results unchanged (E7). Results are captured
  inside the patched window and asserted after restoring, because the assertion library uses the same built-ins.
- **E8:** decoded containers have null prototypes; Object.prototype and Array.prototype pollution does not reach them.

### 2.4 Broken twins (each must make the suite fail)

The meta-test generates 23 twins from `src/encode.js` (one targeted change each) plus one standalone
`JSON.stringify` twin; the list below is the original set, and the meta-test file is the authoritative one.

1. `JSON.stringify` with sorted keys and no domain checks.
2. Accepts floats.
3. Rewrites `-0` to `0` instead of refusing it.
4. Decoder without the re-encode check (last duplicate key wins).
5. No lone-surrogate check.
6. No depth limit.
7. Freezes only the top level.

### 2.5 Gates for this layer

- Mutation score ≥ 95% on `src/encode.js`. Every surviving mutant is either killed or explained in a comment in the
  pull request.
- 100% branch coverage on `src/encode.js`.
- Semgrep: `JSON.parse` is allowed only in `src/encode.js`. No `async`, `await`, `Date`, `Math.random` or imports
  other than `@noble/*` anywhere in `src/`.

## 3. Later layers (outline; each is expanded here before its code is written)

1. **Envelope and record id** (V1–V3): signed-bytes vectors by hand; a record id never changes when only `sig` changes;
   wrong `v`, wrong `type` and swapped-type replay are rejected with their reason codes; SHA-256 checked against NIST
   CAVP (65 short and 64 long messages). A twin that re-serialises the payload before verifying cannot be caught by
   any vector while E2 holds, so a structural test pins that the bytes verified are the bytes received.
2. **Keys and Ed25519** (K1, K2, K4): RFC 8032 §7.1 (5); Wycheproof `ed25519_test.json` (210: 117 valid, 64 invalid,
   29 acceptable — all 29 expected **rejects**); ed25519-speccheck `cases.json` (12, all rejects); ACVP EdDSA SigVer (5).
   Measured: noble with `zip215: false` and Node's WebCrypto both accept all 21 mixed-order acceptable cases, so the
   torsion check is load-bearing; the identity point passes `isTorsionFree()`, so `!isSmallOrder()` is too; and noble
   defaults to ZIP-215, so a twin that omits the option is caught only by dedicated vectors (two are hand-built). A
   small-order component added to R is accepted by noble and rejected by WebCrypto (K4). Twins: `zip215: true`, no
   torsion check, no small-order check, no K4 check.
3. **Root assertions** (W0–W5): Wycheproof P-256 DER (all 484, with `lowS: false`; a broken twin with the default
   `lowS: true` must fail the 71 high-S cases); the W3C WebAuthn L3 §16 vectors, which publish their private keys so
   mutated assertions can be re-signed (3 of the 10 ES256 vectors accept under W2; §16.2's flags 0x19 lack UV); real
   Chrome, Safari and Firefox assertions from the spike, including Chromium's extra `clientDataJSON` key; a software
   authenticator generating assertions, mutated one field at a time; one-directional comparison with SimpleWebAuthn plus the committed list of known differences; broken twins
   with no challenge check, an `endsWith` origin check, UV not required, and trailing authenticator-data bytes
   allowed. W0: `covers` empty, longer than 8, unsorted, with a duplicate, with an uppercase id, or missing the
   record's own id; a challenge computed with the signed-bytes prefix instead of the assertion prefix; one record's
   assertion replayed onto another record not in its `covers`.
4. **Delegation** (D1–D5): window boundaries at `nbf − skew − 1`, `nbf − skew`, `exp − 1`, `exp`; lifetime at the
   cap and one over; a delegation signed by an Ed25519 key; audience spelling variants (trailing slash, uppercase,
   default port, path, userinfo); unsorted or duplicate scopes; F3 monotonicity (no option turns a reject into an
   accept).
5. **Attestation** (A1–A3): witness key outside its window; unknown provider; each provider's account format and its
   near misses (GitHub leading zero or login string; ORCID bad check digit).
6. **Membership, freeze, revocation** (R1–R5): next epoch signed by exactly half (rejected) and by a strict
   majority (accepted); an added root that did not sign; a freeze by a retired root; two valid records for one epoch
   (R3); every permutation of a record set gives the same state (R5, property); a delegation from a root of an older
   epoch; pruning a revocation only after its target's expiry. The three stolen-root scenarios, and traces from the
   Quint/TLA+ model, replayed as tests.

Candidate cases drawn from the published behaviour of Porto, Farcaster and Keybase are added to these sections as they
are expanded.

## 4. How broken twins run

`tests/twins/<layer>/<n>-<name>.js` exports the same interface as the real module. Every test and test helper reaches
the implementation only through `tests/impl.mjs`, which loads the real module or the twin named by an environment
variable; a guard test fails if any test file imports `src/` directly, since that import would bypass the twin. A
meta-test runs the layer's suite once per twin and passes only if every run exits non-zero. A twin that the suite cannot kill is a missing test, and the layer is not mergeable.

## 5. CI order

1. `npm ci --ignore-scripts`, registry signature check, lockfile and pin checks.
2. Semgrep with its rule tests (`semgrep --test`), line budget, duplication check, gitleaks.
3. `node --test` (vector hashes, vectors, properties, adversarial cases), with coverage.
4. Broken-twin meta-tests.
5. Mutation testing on changed core files.
6. CodeQL.
