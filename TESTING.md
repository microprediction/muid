# Test plan

Tests are written and committed before the code they govern, and are seen to fail first. A layer's code is merged only
when its whole section here passes, including the anti-vacuity checks. Rule labels refer to `SPEC.md`.

## 1. Rules for every test

- **One invariant per file:** `tests/<layer>/<label>-<name>.test.mjs`. Mutation testing tracks coverage per file, so
  small files keep it precise and fast.
- **Runner:** `node --test`, no other runner. Property tests use fast-check with a fixed seed in CI and a printed seed
  on failure. `npm test` runs every suite but the broken twins; `npm run test:twins` runs the twin harnesses
  one at a time (each starts its own workers), as CI does within each of its jobs (§7).
- **Vectors are data, not code.** `tests/vectors/<set>/` holds the files exactly as published, plus `SOURCE.md`
  (URL, upstream commit, SHA-256 of each file, licence). A test checks those hashes before using the files.
- **Expected outputs come from outside the code under test:** written by hand, taken from a published vector set, or
  produced by an independent reference. Never generated by the implementation being tested.
- **Anti-vacuity, enforced by tests themselves:**
  - every vector suite asserts the exact number of cases it ran;
  - every property asserts, from fast-check statistics, that most generated inputs exercised the accept path (or the
    reject path, for a reject property);
  - every guard has a broken twin (§6) that the suite must fail against;
  - a skipped or `todo` test fails CI.
- **Rejects are specific.** A reject test asserts the reason code, so a case rejected for the wrong reason fails.

## 2. Layer 1 — encoding (`src/encode.js`): E1, E2, E3

Interface under test: `encode(value) -> string`, `decode(text) -> frozen value`. Both throw `EncodingError` with a
reason code on refusal.

### 2.1 Known answers

- **RFC 8785 reference vectors** (cyberphone `testdata/`, pinned; see `tests/vectors/jcs/SOURCE.md`). None of the six
  cases lies inside our value domain, so (a) each must be refused with its E5 reason, and (b) every string key and
  value in the upstream *outputs* is cut as raw bytes and wrapped as `{"s": …}`; our encoder must reproduce those
  upstream bytes exactly. This is the independent check of string escaping.
- **Hand-written vectors**, written as literals in the test files (`E1-hand-vectors`, `E2-decode-refusals`,
  `E3-value-refusals`): the expected bytes or reason for each case are typed by hand, never computed.
- The reference implementation used in P4 formats strings with `JSON.stringify`, as an encoder of ours would, so P4
  cannot catch a string-escaping error common to both; the upstream vectors above cover that.

### 2.2 Adversarial cases (every one has a vector)

| Input | Expected |
|---|---|
| key `__proto__`, `toString`, `hasOwnProperty` | refused (grammar: leading underscore, uppercase) |
| key `constructor`, `valueof` | encode and decode as ordinary own keys |
| one object reachable by 2^15 paths (a "diamond") | refused with `size` in well under a second (E4) |
| UTF-8 output of exactly 65,536 bytes; of 65,538 bytes with only 32,773 UTF-16 code units | accepted; refused (`size` counts bytes, not code units) |
| keys `"1"`, `"10"`, `"A"`, `""`, a 33-character key, a key with a lone surrogate | refused (grammar) |
| a 32-character key | accepted |
| keys inserted in different orders | identical bytes |
| array hole, `undefined` element, array with an extra own property | refused |
| `-0`, `NaN`, `±Infinity`, `1.5`, `2**53`, `-(2**53)` | refused |
| `2**53 - 1`, `-(2**53 - 1)`, `0` | accepted |
| `null` at any depth; `undefined` as a value | refused |
| BigInt, function, symbol value, symbol key, `Date`, `Map`, `Set`, `RegExp`, typed array, `ArrayBuffer`, class instance, boxed primitive | refused |
| object with an accessor property, a non-enumerable property, or a non-plain prototype | refused |
| cycle; shared subobject at two paths | cycle refused; sharing encodes as its expansion |
| nesting deeper than `MAX_DEPTH`; output longer than `MAX_BYTES` | refused before any stack overflow (E4) |
| **decode** text longer than `MAX_BYTES` | refused without calling `JSON.parse` (E4; checked with a spy) |
| string with lone high or low surrogate; with U+2028, U+2029, U+FEFF, U+0000–U+001F, `"`, `\` | lone surrogates refused; the rest match JCS escaping |
| top-level value that is not an object | refused |
| **decode** text with whitespace, a trailing newline, a BOM, a duplicate key, keys out of order, `\/`, `é` where the canonical form is literal, uppercase `\u001F`, `1e0`, `1.0`, `-0`, a leading zero | refused (E2) |
| **decode** text that `JSON.parse` accepts but that re-encodes differently | refused (E2) |

### 2.3 Properties (fast-check)

- **P1 round trip:** for generated in-domain values, `decode(encode(v))` deep-equals `v`. Implies E1.
- **P2 order independence:** permuting key insertion order at every level never changes `encode(v)`.
- **P3 canonical input:** for any valid encoding `b` and any single-byte mutation, insertion or deletion `b'`,
  `decode(b')` either throws or `encode(decode(b')) === b'`.
- **P4 reference agreement:** for in-domain `v`, `encode(v)` equals the output of an independent RFC 8785
  implementation (dev dependency, pinned).
- **P5 refusal is total:** values from an out-of-domain generator always throw `EncodingError`, never return, and
  never throw anything else.
- **P6 frozen output:** every object and array returned by `decode` is frozen, and so is everything inside it.

Generators cover deep and wide nesting, every string class in §2.2, and integers concentrated near ±2^53 and 0.

### 2.3a Hostile inputs (from adversarial review)

- **H1 resource bounds:** 1e8-character strings (including NUL, whose escaped form exceeds the engine's string limit),
  arrays and objects one element past their width bound, sparse length 2^32 − 1, a dense 2e6-element array: each
  refused for `size` on entry, quickly, and never with a foreign error.
- **H2 Proxies:** traps that throw Errors or non-Errors, revoked proxies, missing descriptors, invariant-breaking
  `ownKeys`, a nested proxy mutating its parent, lengths that change between reads or are not non-negative safe
  integers; and a counting proxy that proves every trap runs at most once per object and property (E6).
- **H3 internal slots:** each detected kind refused when given a plain or null prototype; the residual kinds pinned
  to their documented behaviour.
- **H4 patched built-ins:** 30 built-ins patched after loading (RegExp exec/test, isWellFormed, sort, Number checks,
  JSON, reflection, freeze, iteration, call/apply, the slot checks); results unchanged (E7). Results are captured
  inside the patched window and asserted after restoring, because the assertion library uses the same built-ins.
  Accessors defined on Array.prototype's indices (getters supplying a descriptor of their own) change neither an
  encoding nor a decoding, and are never called (found by review: the encoder's own descriptor list inherited them).
- **E8:** decoded containers have null prototypes; Object.prototype and Array.prototype pollution does not reach them,
  and the copy meets no setter planted on either.
- **E4 order:** a string past the limit is refused as `size` before it is scanned, even with a lone surrogate; one
  within the limit with a lone surrogate is `surrogate`.
- **Lists read once (found by review):** the call's lists elsewhere aside, the pinned witness keys, verifier keys,
  pinned services and a head's revoked list each have their length read once, and refuse one that is not an array
  length without reading an entry; `accept` copies only own fields, never ones inherited from a polluted
  Object.prototype.

### 2.4 Broken twins (each must make the suite fail)

The meta-test generates 27 twins from `src/encode.js` (one targeted change each) plus one standalone
`JSON.stringify` twin; the list below is the original set, and the meta-test file is the authoritative one.

1. `JSON.stringify` with sorted keys and no domain checks.
2. Accepts floats.
3. Rewrites `-0` to `0` instead of refusing it.
4. Decoder without the re-encode check (last duplicate key wins).
5. No lone-surrogate check.
6. No depth limit.
7. Freezes only the top level.

### 2.5 Gates for this layer

- Mutation score ≥ 95% on `src/encode.js`. Every surviving mutant is either killed or explained in a comment in the
  pull request.
- 100% branch coverage on `src/encode.js`.
- Semgrep: `JSON.parse` is allowed only in `src/encode.js`. No `async`, `await`, `Date`, `Math.random` or imports
  other than `@noble/*` anywhere in `src/`.

## 3. Layer 2 — envelope and record id (`src/envelope.js`): V1–V4

Interface under test:
- `open(text, type)` → frozen `{ id, type, body, sig, payload }`, or throws `EnvelopeError` with a V4 reason code.
- `seal(type, body)` → frozen `{ payload, id }`: the payload text a signer signs, and its record id.
- `wrap(payload, sig)` → envelope text; `sig` is omitted for a root.
- `signedBytes(payload)` → a new `Uint8Array` of `UTF-8("muid/v1\n") ‖ UTF-8(payload)`.

Signatures are not checked here; layers 3 and 4 check them over `signedBytes(payload)` of the payload `open` returned.

### 3.1 Known answers

- **NIST CAVP SHA-256** (`tests/vectors/cavp-sha256/`, pinned): all 65 short and 64 long messages through the
  `@noble/hashes` function the layer uses, with the count asserted. This checks the dependency, not our code.
- **Hand vectors:** for three payloads (empty body; a body with non-ASCII text and an escaped control character; a
  body near the size limit) the signed bytes and record id are written as literals, computed outside the project with
  `printf … | shasum -a 256`.
- **Oracle:** for generated bodies, `seal(...).id` equals `node:crypto` SHA-256 of the signed bytes (a second,
  independent SHA-256).

### 3.2 Refusals (every one asserts its reason)

| Input | Reason |
|---|---|
| not a string; whitespace; keys out of order; a duplicate key; trailing newline | `envelope-encoding` |
| extra key; missing `payload`; `payload` not a string; `sig` an array, string or number; a root with `sig`; a non-root without `sig` | `envelope-shape` |
| `payload` that is not canonical JCS, not an object, or contains `null` | `payload-encoding` |
| payload with an extra key, a missing key, `body` an array or string | `payload-shape` |
| `v` of 0, 2, `"1"`, `true` | `version` |
| `type` differing from the expected type; differing only in case; with trailing space | `type` |
| several faults at once | the first in V4 order |
| `open(text, "unknown")`, `seal("unknown", {})` | `TypeError` (programming error, not a refusal) |

### 3.3 Properties

- **Q1 id excludes the signature:** changing only `sig` never changes `id`.
- **Q2 round trip:** `open(wrap(seal(t, b).payload, sig), t)` returns `b` (deep-equal), the same `id`, and the same
  `payload` text.
- **Q3 id commits to every payload byte:** any single-byte change to `payload` either is refused or changes `id`.
- **Q4 refusal is total:** any string, and any envelope built around a mutated payload, either opens or throws
  `EnvelopeError` — never another error.
- **Q5 frozen output** with null prototypes (E8 carried through).

### 3.4 Structural

- The `payload` returned is the received payload text: equal to the substring of `text` that the envelope's `payload`
  decodes to, and `signedBytes` of it equals the prefix followed by that text's UTF-8. A twin that re-serialises the
  body before hashing cannot be caught by any vector while E2 holds; a guard test fails if `src/envelope.js` uses
  `encode` anywhere other than its import and the bodies of `seal` and `wrap`.
- `signedBytes` returns a new array on every call; mutating one never changes another or a later `id`.

### 3.5 Broken twins

No version check; no type check; a root accepted with `sig`; an extra envelope key accepted; id over the payload
without the prefix; id over the whole envelope (so it covers `sig`); the prefix without its newline; `body` allowed to
be an array; output not frozen.

## 4. Layer 3 — Ed25519 keys and signatures (`src/ed25519.js`): K1, K2, K4, K5

Interface under test: `checkEd25519(sig, message, key)` → frozen `{ ok: true }` or `{ ok: false, reason }` (K5).

### 4.1 Known answers (counts asserted)

- **RFC 8032 §7.1** (5): each verifies; flipping any one bit of the signature, message or key makes it fail, with the
  reason K5 order predicts for where the bit is.
- **Wycheproof `ed25519_test.json`** (210): the 117 valid verify; the 64 invalid and all 29 acceptable are rejected.
- **ed25519-speccheck `cases.json`** (12): all rejected, each with the reason written by hand in the test from the
  case's documented construction.
- **Hand-built:** a key and an R that each carry a small-order component (from the eight small-order points), which
  `ed25519.verify` with `zip215: false` accepts and K1/K4 reject; the identity point as key and as R; a non-canonical
  y (y ≥ p) for key and for R.

### 4.2 Oracles and properties

- **Differential, one direction:** whatever we accept, Node's WebCrypto Ed25519 also accepts — over every vector and
  over generated keys and messages.
- **Agreement on honest signatures:** for generated keys (Node `generateKeyPairSync('ed25519')`) and messages, the
  Node signature is accepted; changing one byte of signature, message or key is rejected.
- **K2 total:** for arbitrary strings, numbers, objects and byte arrays as `sig` and `key`, the result is a frozen
  `{ ok, reason? }` with a reason from K5 — never a throw.
- **Hex is canonical:** uppercase hex, odd length, `0x` prefix, whitespace, or a non-string is `key-encoding` or
  `sig-encoding`.

### 4.3 Broken twins

`zip215: true` (in decoding and verifying); no small-order check; no mixed-order (torsion) check; no K4 checks on R;
no S range check (left to `verify`, which must then still reject — so this twin is caught only by its reason);
uppercase hex accepted; a throw from the library escaping; built-ins looked up live; signature checked before key.
Calling the library without `zip215: false` is not a twin: our canonical, prime-order checks run first, so no input
reaches it on which the two modes differ.

## 4a. Layer 3b — P-256 signatures (`src/p256.js`): K2, K6

Interface under test: `checkP256(sig, message, key)` → frozen `{ ok: true }` or `{ ok: false, reason }` (K6).

- **Wycheproof `ecdsa_secp256r1_sha256_test.json`** (484, count asserted): every verdict matches, with
  `sig-encoding` for each BER or malformed-DER case and the 174 valid cases accepted — including those with high S.
- **Differential, one direction:** whatever we accept, Node's ECDSA (OpenSSL) also accepts.
- **Honest signatures:** Node-signed messages are accepted; so are the same signatures with S replaced by n − S
  (passkeys emit both, §2); one changed byte of signature, message or key is rejected.
- **Keys:** compressed (`02`/`03`), hybrid (`06`/`07`), a wrong length, uppercase hex: `key-encoding`; a point off the
  curve, x or y ≥ p: `key-point`.
- **K2:** arbitrary values as `sig` and `key` never throw; built-ins captured at load; built-ins the library uses can
  only make it fail closed.
- **Twins:** `lowS: true` (the library default); `prehash: false`; compressed keys accepted; a throw escaping.

## 4b. Layer 4 — root assertions (`src/assertion.js`): W0–W6

Interface under test: `checkRootAssertion(sig, { record, rpId, origin, key })` → frozen `{ ok: true }` or
`{ ok: false, reason }` (W6).

- **W3C WebAuthn L3 §16 vectors** (pinned excerpt): for each ES256 authentication example, its authenticator data and
  client data are kept byte for byte except the challenge, which becomes a muid challenge, and the assertion is
  re-signed with the published credential private key. Expected: the plain example and the long-credential-id
  example accept (with UV set, as W2 requires — an example without UV is refused as `user-verification`); the
  `crossOrigin: true` and `topOrigin` examples are refused as `client-data`.
- **Browser fixtures:** the shapes measured in Chrome, Safari and Firefox, including Chromium's extra key, rebuilt
  from their recorded layout with a test key.
- **One field at a time:** starting from a valid assertion, each field is mutated (every flag bit; each prefix
  byte; challenge from another record set; origin with a trailing slash, another port, `http`; rp ID hash of a
  sibling domain; trailing authenticator-data bytes; extensions; a second `type` key later in the JSON) and the reason
  is asserted.
- **W0:** `covers` empty, longer than 8, unsorted, with a duplicate, with an uppercase id, not containing the record;
  the record covered together with others (accepted); a challenge computed with `muid/v1\n` (the signed-bytes
  prefix) instead of `muid/v1/assert\n` (refused); one record's assertion replayed onto a record outside `covers`.
- **Encoding:** padded base64url, standard base64 characters, trailing bits not zero, length ≡ 1 mod 4, invalid
  UTF-8 in client data.
- **K2:** arbitrary `sig` values never throw; captured built-ins.
- **Differential, one direction:** whatever we accept, SimpleWebAuthn's `verifyAuthenticationResponse` also accepts
  (it is a dev dependency only; its known stricter or looser points are a committed list).
- **Twins:** no challenge check; an `endsWith` origin check; UV not required; trailing authenticator-data bytes
  allowed; `topOrigin` allowed; the challenge computed over the signed-bytes prefix; covers not required to contain
  the record.

## 4c. Canonical origins (`src/origin.js`): O1

- **Hand cases:** accepted — two labels, many labels, digits and hyphens inside labels, port 1, 444, 65535, a
  63-character label, a 253-character host. Refused — `http`, uppercase anywhere, a trailing dot or slash, a path,
  query, fragment or userinfo, port 443, 0, 65536, a leading zero, an empty port, one label, an empty label, a label
  of 64 characters, a 254-character host, leading or trailing hyphen, `xn--` and any `??--` label, an IPv4 or IPv6
  host, percent-encoding, whitespace or control characters anywhere, a non-string.
- **Oracle, one direction:** whatever is accepted, the WHATWG URL parser (Node's) agrees is an origin and serialises
  to the same string: `new URL(x).origin === x`.
- **Property:** generated hosts and ports in the grammar are accepted; every single-character mutation of an
  accepted origin is either refused or still satisfies the oracle.
- **Twins:** uppercase allowed; port 443 allowed; trailing slash allowed; `xn--` allowed; IPv4 allowed; no length
  limits.

## 4c2. Roots and identities (`src/root.js`)

- **Hand vectors:** a root record's id and its identity id, computed outside the project with `printf … | shasum`.
- **Refusals:** each V4 reason through `checkRoot`; `root-shape` for a missing, extra or non-string key and for `pub`
  not 130 lowercase hex starting `04`; `rp-id` for another rp ID, a different case, a trailing dot; `key-point` for a
  point off the curve.
- **Binding:** the id changes with the rp ID and with any key byte; the same key under two rp IDs gives two roots.
- **K2:** arbitrary texts never throw; `identityOf` refuses anything but a 64-hex id as a programming error.
- **Twins:** id without the domain prefix; id over the hex text instead of the bytes; rp ID not compared; identity
  over the hex root id.

- **Agent ids (D8, `R0-root.test.mjs`):** `agentIdOf` equals SHA-256 over the specified bytes, computed with
  `node:crypto` (`"muid-agent\n"`, the identity id's 32 raw bytes, the name), for names of 1 and 64 characters; it
  differs per identity, per name and from the identity id; a malformed identity id or name is a programming error.
  Twins: the prefix omitted; the identity omitted.

## 4d. Layer 5 — delegations (`src/delegation.js`): D1–D8

Interface under test: `checkDelegation(text, ctx)` → frozen `{ ok: true }` or `{ ok: false, reason }` (D7), with
envelopes made by the real `seal` and `wrap` and `sig.root` a real passkey-shaped assertion (as in §4b).

- **Window (D1):** `now` at `nbf − skew − 1` (`not-yet`), `nbf − skew` (accepted), `exp − 1` (accepted), `exp`
  (`expired`); skew never extends `exp`.
- **Lifetime (D2):** `exp − nbf` at `maxLifetime` (accepted) and one over; `exp = nbf`; `exp < nbf`.
- **Shape:** each of the eight keys missing, an extra key, each field of the wrong type or form (uppercase hex, 63 or
  65 characters, a float or unsafe time, a string time); `sig` without `subject`, with an extra key, `subject` not
  128 hex.
- **Scopes:** empty, 17, unsorted, duplicate, uppercase, a 65-character scope, a scope starting with a digit; 16
  accepted.
- **Audience:** every refused case of §4c gives `aud`; a canonical origin is accepted.
- **Subject key (K1):** a small-order and a mixed-order key give `subject-key`.
- **Root binding:** a body naming another root, a key that is another root's, the right key under another rp ID —
  each `root`, before the assertion is checked.
- **Result and context:** an accept carries `id` and `body`, frozen; each context field is read once.
- **Root assertion:** an assertion covering another record (`covers`), one signed by another passkey (`sig-invalid`),
  one whose covers include this record and others (accepted).
- **Subject consent (D6):** signed by another key; over the hex id instead of its bytes; with the signed-bytes or
  assertion prefix instead of the accept prefix; over another delegation's id — each `subject-consent`.
- **Context:** a context that is not well formed (`now`, `skew`, `maxLifetime` not non-negative safe integers; keys
  not strings) is a programming error.
- **K2:** arbitrary texts and values never throw; envelope faults give V4's reasons.
- **Twins:** skew applied to `exp`; `<=` at `exp`; no lifetime cap; scopes prefix-matched or unsorted allowed; no D6;
  D6 over hex text; aud not checked; root assertion checked against a fixed record id.
- **Agents (D8):** `agent` missing, empty, upper-case, starting with a digit, with a space or a slash, of 65
  characters, non-ASCII, a number, a list or a boolean is `delegation-shape`; names of 1 to 64 characters of the scope
  grammar are accepted. Twin: a name of any form accepted.

## 4e. Layer 6 — attestations (`src/attestation.js`): A1, A3, A4

- **Accounts:** GitHub `1`, `583231`, a 20-digit id (accepted); `0`, `01`, 21 digits, `-1`, a login (refused).
  Google: a 21-digit sub, 255 printable characters (accepted); empty, 256 characters, a space, a non-ASCII

- **Witness keys (A1):** an unpinned key; a pinned key before its `nbf` and at its `exp`; a pinned key inside its

- **Window and lifetime:** as for delegations (§4d).
- **Signature:** over the signed bytes, by the named key; any change to the payload or signature is refused.
- **Shape, totality, context read once,** as for delegations.
- **Twins:** no check digit; leading zeros allowed; any provider; witness found by trying keys; key window ignored;
  signature over the payload without the prefix.

## 4f. Layer 7 — membership state (`src/membership.js`): R1–R8

- **The model as oracle:** every state `model/settled.mjs`'s explorer reaches in five scenarios (one root stolen; two
  roots, the later stolen; three roots, a later or the first stolen; three roots, two stolen) — thief moves, owner
  answers, then the window closing — is translated into real signed records (P-256 roots, an Ed25519 witness), and
  `membershipState` must give the model's answer. The scenarios together must reach dead, frozen, pending and settled
  states. Sampled partial views (subsets a network attacker could show) must agree too. Under a small `FC_RUNS` a
  deterministic sample is used, keeping every dead and frozen state.
- **Random walks past the explorer's bound (`R8-walks`):** from the same scenarios, walks of up to eight moves by the
  thief, the owner, the witness clock or a lying witness (a stolen witness key: anchors and settlements of its
  choosing, shown only to verifiers, the witness service keeping its own log). After every move, and on a partial view
  of the last state, `membershipState` must give the model's answer; the service's own items must have no forked
  view. 200 walks per run (about 10 seconds), 5,000 in the nightly fuzz job. The walk generator, sampled from the
  pinned seed through the model alone, must reach dead, frozen, pending and settled states, two epochs past the history, eight moves, and states after a lie,
  so that this holds at any `FC_RUNS`. Against the twins: 200 walks catch the four the
  explorer catches (added roots unsigned, new roots' authority while pending, a freeze lifted at anchoring, settlements
  ignored) in a sixth of its time; 5,000 also catch half counted as a majority, a contest without one, and one of two
  anchored rivals chosen, which the explorer cannot reach because its witness is honest.
  A record that skips an epoch, signed by a majority and anchored, is ignored by the model and `membershipState` alike
  (the model lacked the check; found by review).
- **Hand cases:** memberships of every wrong shape (extra key, empty, six roots, unsorted, duplicate, non-id roots,
  wrong epoch, another identity, bad `prev`) ignored even when anchored; witness records with a bad signature shape,
  a negative `at` or a bad outcome ignored; contests and freezes of non-ids ignored; a witness that anchors two
  rivals ends the identity; witness keys outside their window at the record's `at`; assertions over another record
  or by a key that is not the named root; a signer whose root record is missing; unreadable `records`.
- **Order-free (R7):** in a settled, a frozen pending and a dead scenario, every list permuted, records repeated and
  another identity's valid records mixed in (property; most runs include them): the state is unchanged.
- **Tamper sweep:** a pending epoch over a settled one, frozen by a root of the pending record; a one-character change
  (two replacements and a deletion) to any one record gives the state with that record or without it, never another,
  and each kind holds a record whose loss changes the state. Positions are sampled with a fixed seed;
  `MUID_SWEEP=full` sweeps every position.
- **List lengths:** a list whose length is not an array length (an object whose `valueOf` says 0 to the cap and
  5,000 afterwards, `NaN`, a fraction, a negative, `Infinity`, a string, 2⁵³) is refused as `records` with no element
  read (found by review).
- **Twins:** half counted as a majority; added roots not required to sign; the witness window ignored; a contest
  without a majority; new roots with authority while pending; a freeze lifted at anchoring; settlements ignored; one
  of two anchored rivals chosen; root assertions not verified; the revocation cap applied only after the whole list is
  read; a pending epoch in the head as if settled.


## 4g. Layer 8 — the verifier (`src/verifier.js`): F1–F5, R9

- **Accept path:** a delegation, its root record and a fresh head give the delegation's id and body.
- **Head:** another type, an extra key, empty or three memberships, a repeated membership, no or six roots of
  authority, unsorted or repeated authority, ids with junk, a non-integer `at`, an unpinned witness, a signature by
  another key than named, a key whose window does not hold `at` — each `head`.
- **Staleness:** exactly `maxStaleness` old (accepted) and one second more; `skew` in the future (accepted) and one
  second more; `at = 0`.
- **Composition:** root-record refusals; D7's reasons passed through (including `root` for another root's record);
  identity, membership (settled and pending both accepted) and authority judged by the head; revoked, audience, scope.
- **Revocation and lag (R9):** the head's revocations by delegation id and by subject key; `minHeadAt`; a witness key
  whose window holds the head's `at` but not `now`, or ends exactly at `now`; malformed revocation entries are a
  programming error.
- **Equivocation (decision 10):** with `lastHead`, an honest witness's later heads are accepted (the same state, a
  successor pending, it settling, the next pending, two epochs on, authority shrinking when a successor turns pending
  and growing when it settles, and changing freely one epoch on from no pending successor or two epochs on); a lower settled epoch, another settled membership at the same epoch, a pending
  successor gone or replaced, the next epoch settling another than the pending successor, one membership at two
  epochs, more or less authority over the same memberships, authority growing as a successor turns pending or shrinking as
  it settles alone, and two heads of one second inconsistent both ways round are `equivocation`; a head of the same
  second that could honestly precede the last one is `stale` (including one without a revocation the last carried,
  under the same memberships; across a membership change in that second, revocations imply no order), as is an older head, even a consistent one; a last head of another identity is `identity`, never a throw; a last head signed by a key since retired
  still works; a last head that is not a pinned head is a programming error. Over every pair of a pool of heads, a
  last head only removes trust (F3). Head form: `epoch` a positive integer, 1 exactly when the first membership is the
  identity.
- **Equivocation against the model:** over every history the explorer reaches with an honest witness (two and three
  roots, epochs to 3, every move by an actor holding every root, and ticks; about 18,000 states), every head is
  consistent with every head signed before it on the same history (the rule restated over epochs and sets, apart from
  the code), with every progression the rule distinguishes, changes of authority, and (heads carrying R10's
  revocations, one per live membership and root) a head of one second dropping a revocation reached; stricter rules refuse
  some honest pairs, so the check has teeth. Heads from diverging histories are refused in part. Through the real
  verifier, every distinct honest pair is accepted in order and is `stale` reversed (including pairs of one second),
  and 300 diverging pairs, some of one second, are `equivocation`.
- **The time model (`F-time-model.test.mjs`, `model/timing.mjs`):** a model of F5's time and revocation rules
  written from this spec, not the code: D1 and D2, the head's key window and freshness (R9, `minHeadAt`,
  `lastHead`), heads of one second (decision 10), revocation in the head, the call or the last head, and R10's
  windows. A verifier with small windows (skew 2 s, lifetime 12 s, staleness 8 s, two overlapping witness keys) puts
  every boundary within reach: 600 generated calls, each refused with the model's reason or accepted as it is, and
  `verifyHead` giving its head checks; then 150 traces in which an honest witness revokes and lets an id's revocation
  lapse after expiry plus `skew`, an attacker replays any head signed so far, and the relying party remembers the
  newest head that verifies alone (§7). At every presentation the verifier agrees with the model; once the memory
  holds a head revoking the delegation nothing is accepted; an honest witness's head is never refused as
  `equivocation`. The generators, sampled from a pinned seed through the model alone, reach acceptance and every
  reason. It catches each of the 22 twins within its scope; the rest (epochs, authority, claims, shapes) are other
  sections' (writing it from the spec found that F5 did not say the last head's revocations count, which the code and
  `F7-logged` already required).
- **Logged (R10, `F7-logged.test.mjs`):** accepted with the witness's logged record naming the delegation; a logged record before its delegation's `nbf` less `skew`, or at its `exp`, refused, and the key window's edges tested under a delegation whose window holds them; a revocation (by id or subject key) in the last head refuses the delegation under a later head without it, another revoked does not (found by review); a signed logged record of the wrong form (an `at` that is an array, an object, a string, a boolean or negative; an identity or delegation that is not an id) refused as `logged`, never thrown on (found by the fuzz test); `logged`
  for none, a non-text, a non-envelope, a head, another delegation's or identity's record, an extra key, no time or a
  time that is not a number, an unpinned key, a forged signature, a time before or after the key's window (its first
  second counts); checked after `revoked` and before `audience`; read once.
- **F3:** adding revocations never turns a refusal into an accept (property).
- **Programming errors** for configuration, `now`, `scope`, `revoked`, `minHeadAt`, a claim call's `method`, `url`,
  `nonce` and `contentDigest`, and `lastHead`; the configuration is copied at
  construction; arbitrary and hostile records never throw.
- **Claims (C1):** accepted with id, body, delegation and `until`; every shape fault (extra key, missing or
  non-object data, bad delegation id or scope, `htm` not upper-case letters, `htu` without a path, with a query or
  fragment, over http, with a non-canonical origin, a space, a bare or lower-case escape, a nonce outside NQCHAR, a
  digest not canonical base64 of 32 bytes, negative or string time, signature not exactly 128 hex or not alone) is
  `claim-shape`; a claim for another scope, method or URL (another origin's URL refused even where that origin is
  passed; the received URL's query and fragment dropped; a received URL outside the grammar refused, not thrown; so
  is a received method outside it — lower-case, empty, with a space, of 17 letters as a registered method may be, or
  of 1,000 — and an `htm` of 17 letters is `claim-shape`, of 16 accepted (found by review); a nonce over 256
  characters in the call is a programming error); a
  nonce or digest missing, unexpected or different; the request checked in order before the delegation; the delegation verified in
  full; another delegation named; time at and one past `maxClaimAge` and `skew`, and outside the delegation's window;

- **Bounded head building:** `headOf` given 2,000 distinct descending revocations reads exactly 65 entries.
- **Tamper sweep:** every position of the claim, its delegation, the root record and the head, replaced two ways

## 4h. The relying-party adapter (`adapter/`, not core): issue #21

- Atomicity: twenty concurrent requests in one process, and eight worker threads on one SQLite file released by a
  barrier, present one claim: exactly one runs the action. A request whose transaction waits behind one that stores
  a head revoking its delegation is refused as stale. A SQLite store opened while another connection is writing a
  new file waits for it and then opens (SQLite itself refuses at once there, which failed about one start in
  twenty of eight instances together); it waits `busy` milliseconds and no longer, and not at all for a file that is
  not a database.
- Memory: the head only moves forward, in both stores and under a late writer; an older head is then refused; a
  stored head the verifier cannot read (corrupt, or signed by a removed witness key) bounds rollback by its time.
- Failure: a failing transaction or any of its operations is refused as `storage`, and the action does not run; a
  SQLite transaction that fails is rolled back; a malformed call still throws.
- Boundaries: claim ids expire exactly at `until`, when the verifier already refuses the claim by its time.
- The call is read once, field by field, and the request's nonce and body digest reach the verifier (a twin drops
  the nonce).
- Broken twins (`tests/meta/adapter-twins.test.mjs`): the memory not read in the transaction; a memory read failure
  taken for a verifier error; a consumed claim accepted again; a failed transaction taken as success; the stored
  head not passed; an unreadable stored head locking its identity out, or its time ignored; the records read twice;
  heads regressing in either store; a store that gives up at once on a locked new file, or waits on any error.
- **Replay after cleanup (found by model checking):** a replay whose transaction waits, while another instance's
  cleanup drops the claim's id, is refused as `claim-time` once the waiting instance's clock passes the claim's
  `until` (memory and SQLite stores; the trace TLC found, replayed against the adapter). An adapter without a
  `clock` is a programming error.
- **Authorised at the transaction's time (found by review):** with signed fixtures and both stores, for `acceptClaim`
  and `acceptDelegation`: a request verified on arrival and then held, while the delegation expires, the head
  becomes too old or the witness key's window ends, is refused with the reason the verifier gives at that time, its
  action not run and its claim not consumed; the same request held until one second before the deadline, or not
  held, is accepted. A request the call's time refuses is not accepted because the clock, behind it, would. A clock
  that gives no time is a programming error, and nothing is remembered. Twins: the transaction verifying at the
  time the request arrived; the call's time ignored; the clock unchecked.

## 4h2. Model checking (`model/tla/`, TLC)

- **The adapter (`Adapter.tla`):** an honest witness that may revoke the delegation; an attacker holding the
  delegate's key, who signs claims with any time and presents any claim with any signed head, to either of two
  instances whose clocks differ by 2 s, sharing one durable store; each request verified alone, then in a transaction,
  with the other instance's requests, cleanup of expired ids, restarts and time passing in between. Explored
  exhaustively: each claim is dispatched at most once; nothing is dispatched once the store remembers a revoking head;
  a request is authorised, at its transaction, only while its claim's age, its delegation's window, its head's
  freshness and the witness key's window all still hold by its instance's clock (`NoExpiredAuthorizationAtCommit`);
  and it is authorised at most `maxStaleness` plus the clock difference after the revocation, a bound TLC showed is
  reached. About 24 million states, a minute or so. Negative controls, each of which TLC must report: with the grace
  below the clock difference, or without the claim's age checked at the transaction, a claim is dispatched twice;
  without the delegation's window, the head's freshness or the witness key's window checked there (three
  configurations), a request is authorised past that deadline; with the freshness limit one second tighter, it is
  exceeded, so the limit cannot be improved. TLC first found the adapter's own double dispatch (a request that waited
  outlived its id's stay in the store), fixed in §4h; the other deadlines were found by review, and the model had
  not stated the property they break.
- Run by `.github/scripts/tlc.sh`, the tools at a pinned release checked against their recorded SHA-256; a passing
  configuration must find no error, and each negative control must report the violation it names.

## 4h3. Protocol proofs (`model/tamarin/`, Tamarin)

- **The authentication chain (`Claims.spthy`):** against a network attacker who may also steal any root or delegate
  key, for any number of sessions: an accepted delegation was authorised by the identity's root unless that root key
  leaked; an accepted claim under an honest delegate's key was signed by it for exactly that request unless that key
  leaked; no identity can count another identity's delegate as its own, even with its own root key stolen, unless
  the delegate's key leaked; a claim accepted at one audience was made for it. An honest run exists (anti-vacuity).
  The owner may authorise any key it is given, an attacker's included: the id page's defence is the fingerprint the
  user compares, outside the protocol, so the claim and consent lemmas are about honest delegates' keys (Tamarin's
  first traces were exactly that).
- **Two defences for consent, each enough alone:** D6's consent and a claim naming its delegation's id. Without either
  the lemma still holds; without both Tamarin finds the attack. The three controls are one-line edits of a copy, made
  by `.github/scripts/tamarin.sh`, which fails if an edit no longer applies or a result differs from the one written.
- Tamarin 1.12.0 and Maude 3.5.1 from pinned releases, each checked against the SHA-256 its release publishes.

## 4m. Patched built-ins (`tests/patched/`, §4 FAIL CLOSED UNDER PATCHED BUILT-INS)

Every function-valued property of the standard prototypes and namespaces the core and its libraries can reach (about
300: `Array`, `String`, `RegExp`, `Object`, `Number`, typed arrays, `ArrayBuffer`, `DataView`, `Map`, `Set`,
`TextEncoder`, `TextDecoder`, `BigInt`, `Error`, `Math`, `JSON`, `Reflect`, and their prototypes) is replaced, one at a
time, by a stand-in that throws, one that answers true and one that returns its receiver, and a battery runs under each.
A result may stay what it was or fail closed (a refusal or a throw), nothing else.

- **The verifier (`P1`):** 18 record sets that must be refused (consent or a root assertion by another key, a tampered
  payload, revoked by id, subject key or agent, expired, not yet valid, stale, a head by an unpinned key or for another
  identity, a root without authority, another audience, an ungranted scope, not logged; claims by another key, for
  another URL or too old) and two valid sets. Shown a verifier whose audience check calls `startsWith` on the received
  string, it names the patch that makes another audience accepted.

  a lying witness. Found by this sweep: `membershipState` kept its tables in `Map` and `Set` and called `.some` on its
  own lists, so a patched `Set.prototype.has` answering true counted a record half the roots signed as a majority; and
  noble, which does not capture its built-ins, could be made to fail every signature, so that every record was
  ignored and the identity reverted to its first root, a dead one revived. Fixed by null-prototype tables and index

## 6. How broken twins run

`tests/twins/<layer>/<n>-<name>.js` exports the same interface as the real module. Every test and test helper reaches
the implementation only through `tests/impl.mjs`, which loads the real module or the twin named by an environment
variable; a guard test fails if any test file imports `src/` directly, since that import would bypass the twin. A
meta-test runs the layer's suite once per twin and passes only if every run exits non-zero. A twin that the suite cannot kill is a missing test, and the layer is not mergeable.

## 7. CI

Every pull request and push runs the quick jobs, in parallel, so it is done in about a quarter of an hour; the slow
ones run nightly (and on demand, from the Actions tab), and a nightly failure is fixed the next day.

1. **Tests** on Node 22, 24 and 26, on every run: `npm ci --ignore-scripts`, the registry signature check, then
   every suite outside `tests/meta/` (vector hashes, vectors, properties, adversarial cases, guards) with 100%
   coverage of `src/`.
2. **Twins:** the quick harnesses in `tests/meta/` on every run, in three jobs, each run one after another; the
   slow ones (the id page, the witness) nightly, a job each.
3. **Mutation testing:** one config per module. Nightly, every config: the slow ones (the id page, membership, the
   witness) a job each, the others in two. On every push to master, the quick configs, in one job. On a pull
   request, the quick configs whose inputs it changes (`tests/mutation-plan.mjs`): the files a config mutates, its
   test files, and everything those name by a relative path (an import, a URL, a directory served or read),
   followed transitively; the package files and the workflow are inputs of every config. A core module is reached
   by every suite through `tests/impl.mjs`, so a change to one runs every quick config; documentation runs none.
   A path built at run time is not seen, and the nightly run catches what a pull request's run missed.
4. **Fuzzing** (`fuzz.yml`, nightly, not gating): every property test at 25 times its count with a new seed, and
   coverage-guided fuzzing with Jazzer.js (libFuzzer), 15 minutes for each target in `fuzz/targets/`, from its seeds
   in `fuzz/seeds/`, with only `src/` instrumented. The targets: `decode` (refuses only with an EncodingError, and
   what it accepts `JSON.parse` reads the same); `client-data` (any `clientDataJSON`, signed by the passkey, so W1's
   hand-written prefix check is reached: never a throw, and an assertion it accepts is read by `JSON.parse` as W1
   requires, with no `topOrigin` and every other member a string); `verify` (a valid claim, delegation, root, head and
   logged record, one spliced: `verifyDelegation` and `verifyClaim` never throw, and accept nothing changed).
   Jazzer is installed apart from the repository, in `fuzz/` with its own lockfile (105 packages, none with an install
   script, SLSA provenance, prebuilt N-API binaries), held by the pin guard and the release-age check to the
   repository's rules; its registry signatures are checked before it runs. On every pull request
   `tests/fuzz/F-seeds.test.mjs` runs each target on each seed without the fuzzer, so a target that breaks fails then,
   not at night, and the job's list of targets must be the targets there are. Shown planted faults, the fuzzer found
   each within a minute or two: head signatures unchecked, a duplicate `type` read by `JSON.parse` differently,
   `topOrigin` accepted, and text after the closing brace accepted.

Stryker's incremental mode was not used for this: it "will not detect any changes you've made in files other than
mutated files and test files", and the tap runner reports results per file, not per test.

Guards fail the build if a test file is in no job, a module has no mutation config, or a config is in no mutation
job (the plan's tests were each seen to fail on a planted fault), and if a dependency is not pinned (exact versions, a lockfile that agrees, the public registry over https
with sha512 integrity, no install scripts, nothing at runtime but the two noble packages); the pin guard runs against
eighteen edited copies of the real files and must name each fault. Every property test takes its run count from
`tests/runs.mjs` (`FC_RUNS` sets every count, `FC_SCALE` multiplies each file's own), and a guard, shown planted
faults, fails a test file that reads `FC_RUNS` itself or sets a count of its own. The scan workflow (`.github/workflows/scan.yml`)
runs CodeQL, Semgrep with its rule tests, gitleaks over every commit, jscpd against its reviewed baseline, and the
release-age check; each was shown to fail on a planted fault (a result, a broken rule, a token, a copied file, a
too-new package) before it was relied on. `tests/assertion/W-simplewebauthn.test.mjs` is the SimpleWebAuthn
differential, with its known differences pinned.
